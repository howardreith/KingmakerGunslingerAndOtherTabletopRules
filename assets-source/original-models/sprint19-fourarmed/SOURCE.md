# Sprint 19 original bodies: Girallon and Xill

Both bodies are project-owned geometry, generated by the scripts in this
directory. No proprietary mesh, texture, shader or animation is read, and none
is redistributed.

## The one game-sourced input

The donor bind-pose skeleton: bone names, their bind positions in the local
frame of the donor renderer, and the parent links between them. Nothing else.
No vertex, index, UV, texture pixel, shader or animation curve is read.

That capture is the Sprint 18 guarded primate donor census, reused rather than
re-run:

The capture lives outside the repository and is never committed; only its hash
is published.

**Why no new census.** Sprint 18 surveyed 28 rigs under a guarded read-only
run and chose this one. Both Sprint 19 creatures are bipeds of the same broad
build, and the installed library has no four-armed primate and no xill, so
neither can clone a native body either. Re-running a guarded capture to
re-derive the same answer would spend an owner runtime transaction to learn
nothing. The reuse is verified rather than assumed: the capture is re-decoded
at intake through the same validator, and the bone graph, driver set and bind
height above are what it returned.

## Four arms on a two-armed rig

Both creatures print four arms. The donor has two.

No four-arm rig is built, no bone is invented, and no general arbitrary-limb or
retargeting framework is written — all three are out of scope. Each side's two
arms are skinned to that side's single existing driver chain
(`Clavicle_01`, `Up_Arm_01`, `Forearm_01`, `Forearm_02`, `Hand_01` and the
digits below them), with the lower arm's geometry offset down and out from the
upper arm's and built slightly smaller.

**`FOUR_ARMS_SHARE_TWO_DRIVER_CHAINS`.** Both right arms therefore swing
together on the donor's right-arm animation, and both left arms on its left.
For a creature whose printed routine is four claws striking one target in one
sequence this reads correctly, but the lower arms cannot be posed
independently of the upper. That is stated here, in each shipped mesh's own
`authoredLimitation` field, in the runtime binding contract, and in the release
notes. The runtime refuses a body that declares anything else, so a mesh cannot
quietly claim a rig this project did not build.

`test_fourarmed_prototype.py::test_each_driver_chain_carries_two_arms` is the
check that makes this more than a claim: it reads the built geometry and
requires each side's arm bones to drive two clusters of vertices separated by
at least the authored drop. A render can be looked at and a manifest field can
be believed; that test can only pass if the geometry is really there.

## What is NOT authored

- **No animation.** Kingmaker plays the donor rig's own clips, which belong to
  a large upright biped. The geometry is a girallon and a xill; the walk, run
  and strike timing are the donor's. A faithful gait would be a general
  animation system, which this sprint does not build, so the shortfall is
  recorded rather than hidden.
- **No creature, limb or retargeting framework.** Every number in the
  generator is a measured offset from one named bone of one named donor.
- **No game state.** The scripts read one private capture file and write into
  a private output directory.

## Reproduction

From this directory, with Blender 4.5 and the private capture:

```
blender -b --factory-startup -noaudio --python paint_fourarmed_albedo.py -- \
    --kind girallon --out <out>/girallon-albedo.png --size 1024
blender -b --factory-startup -noaudio --python generate_fourarmed.py -- \
    --kind girallon --capture <census.json> \
    --albedo <out>/girallon-albedo.png --mesh-data <out>/girallon-mesh.json \
    --report <out>/girallon-report.json --blend-out <out>/girallon.blend
blender -b --factory-startup -noaudio --python render_fourarmed_review.py -- \
    --blend <out>/girallon.blend --out-dir <out>/review --suite
blender -b --factory-startup -noaudio --python test_fourarmed_prototype.py -- \
    --capture <census.json>
```

The painter is deterministic: every pixel comes from seeded noise and the
region layout, so the same command always writes the same bytes. Nothing is
sampled from the game, from a photograph, or from any other image.

## What is shared with Sprint 18, and why

The exporter, the triangle winding convention, the eight-region UV atlas, the
donor capture validator and the review renderer are Sprint 18's, imported
rather than copied. They are genuinely the same thing: the same rig, the same
bind frame and the same triangle order, which is why both Sprint 19 meshes
declare the Sprint 18 winding marker `shared-exporter-sprint18`. A second copy
would be a second thing to keep right.

Nothing about the two creatures' shapes is shared. The Girallon is an upright
white-furred ape with a deep chest, a crested skull, a prognathic muzzle and
four bared canines; the Xill is a chitinous outsider with a segmented abdomen,
thin jointed limbs, digitigrade legs, four compound eyes and mandibles. They do
not even share a noise field: fur is painted lengthwise and soft, chitin is
painted as hard-edged segment banding with a lit plate crown.

## Review history

The bodies went through four offline passes, each from a render rather than
from a preference:

1. The claws on four hands read as a bundle of spikes, so they were shortened.
2. The Girallon wore a pale card across its face: the whole prognathic muzzle
   had been assigned to the `mouth` atlas region, which is painted half gum and
   half tooth. The muzzle is facial hide and now sits in `face`, with only the
   mouth opening left in `mouth`.
3. A creature the stat block calls white rendered grey, because the hair was
   painted at 0.72 over a 0.40 root and the strand modulation multiplies by as
   little as 0.80. The coat and its roots are lighter now and the limb
   darkening is gentler.
4. The review renderer recursed infinitely on any Sprint 18 pose, because it
   rebound the shared module's `apply_pose` and then delegated through the same
   name. It captures the original function first.
